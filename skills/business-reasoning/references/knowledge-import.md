# 接入知识与分类

知识内容由使用者单独提供。Skill 可直接读取用户指定文件；有工作台时也可导入本地知识包。方法记录与案例证据分开保存，导入知识不代表其内容已核实或授权重新分发。

## 统一记录

知识包包装为 `{ "schema_version": "1.0", "records": [...] }`，完整字段见 [knowledge.schema.json](knowledge.schema.json)。

- `id`：唯一的版本化记录 ID，不用标题充当 ID。原始记录的逻辑身份另行保留；内容或标签修订时生成新的版本 ID，保留原记录和版本映射，避免覆盖已被历史案例引用的方法。
- `title`、`body`：方法标题与完整内容。`body` 可为文字或结构对象，适合保留步骤、图形节点/边、指标、输入输出和来源问题。
- `source.document`、`source.page_numbers`：原文档和实际页码；不知道时保留空页码，不猜测。
- `family_ids`：同源身份，用于避免将不同表示重复计为证据。
- `limitations`：前提、图形关系待核项、范围限制及抽取问题。
- `scenario_ids`、`method_type_ids`、`management_levels`：三轴导航标签，使用 [taxonomy.json](taxonomy.json) 中的 ID。

不必为了迁移把原始 PDF 或图片放入 Skill。原件在用户自己的知识目录保存，用外部索引定位；打包 Skill 仅包含其工作指令与公开资源。需要迁移原件时，由用户选择单独的知识包。

## 离线映射已有资料

先盘点原记录的 ID、标题、摘要、适用场景、输入输出、标签与来源。在本地映射表保留旧 ID 和完整正文；为带新标签的版本生成新记录 ID，不改写原图关系和来源证据。

1. 场景看“帮助做什么决定”。例如补货、调拨、可售和库存问题可成为 `merchandise-inventory` 候选；仅出现“增长”不代表适用于完整增长诊断。
2. 方法类型看“如何推理或操作”。分组比较映射 `segmentation-comparison`；输入—动作—输出的路径映射 `process-mapping`；指标恒等拆解映射 `metric-decomposition`。图形形式本身不总能决定方法类别。
3. 管理层级看“谁在什么范围内做决定”。现场执行、跨店配置和总部规则可以重叠；没有充分依据时不强行选层级。
4. 目录或关键词映射只产生候选标签。读取完整材料后确认；有冲突则记录待审核。记录内可附 `classification: {status, basis, reviewed_at}`，明确这是导航判断而非原文分类。

候选映射和原 ID 对照表留在用户本地知识目录，不随公共 Skill 发布。批量映射完成后检查未知标签、重复 ID、遗漏来源、孤立方法与候选状态；不能以“全部有标签”代替适用性检查。

## 扩充与迁移

新增知识时先确定是方法、案例还是原始证据，保留其身份。方法更新后重新核对仍在使用该方法的案例结论，不能默默追改历史答案。跨 Agent 迁移时携带 Skill 和选定的知识/案例文件，记忆不会因为 Skill 同名而自动同步。
